## IndicVoiceCare comparison

The inspected [app.py](https://github.com/kowshik568/IndicVoiceCare/blob/main/app.py) implements a server-side request with `X-API-Key-ID`, JSON `prompt`, and a JSON envelope containing `response` text. Its [README](https://github.com/kowshik568/IndicVoiceCare/blob/main/README.md) supplies an example Evon URL. That code demonstrates a transport assumption; it supplies no evidence that the URL is currently official, available, or entitled for this participant account. Its public `.env` was not read.

DriveOS currently differs: its explicitly configured base URL receives `/chat/completions`, a `model` plus `messages`, optional Bearer authentication using only `EVON_API_KEY`, and expects `choices[0].message.content`. It does not reuse the participant speech key. Therefore even a functioning IndicVoiceCare-style endpoint would require verified transport/auth details before adapting it; the two request formats are not interchangeable.

The official [challenge](https://www.gnani.ai/internship) describes Evon v3.3 as open weights available by request on Hugging Face. The [registration page](https://www.gnani.ai/great-indian-ai-internship-registration-form) separately points participants at Gnani API documentation including LLMs and directs them to download/run Evon. Neither establishes this account's hosted Evon completion URL, accepted model alias or authentication. The [model card](https://huggingface.co/gnani/gnani-evon-v3.3-30B-A3B) documents deployment; weight access and participant API credits are not evidence of hosted inference entitlement. The same hosted approach is not currently established as available to DriveOS.
